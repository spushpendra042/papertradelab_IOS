# PaperTradeLab — Android + iPhone app (Flutter)

Subscription-gated live strategy signals, paper-trade execution (buy / sell / follow a signal /
reset balance), open track record, signal history, live P&L, in-app Cashfree payments, log-in-once sessions, optional push notifications.

This folder contains the app code (`lib/`, `pubspec.yaml`) plus the launcher icons. The Android
and iOS wrapper folders are generated by Flutter (on GitHub or on your machine), so they always
match the installed Flutter version. One code base builds both apps.

| I want to…                                   | Run this GitHub Action                         | Needs                                    |
|----------------------------------------------|------------------------------------------------|------------------------------------------|
| an APK for Android phones                    | **Build APK**                                  | nothing                                  |
| an iPhone build for myself / a few testers   | **Build iOS IPA (unsigned, for sideloading)**  | any Apple ID + Sideloadly or AltStore    |
| a link every iPhone user can install from    | **Build iOS (TestFlight / App Store)**         | Apple Developer Program ($99/yr), section 8 |

## 0. Easiest way to get an APK — no installs (GitHub builds it for you)

1. Create a free GitHub account and a new **private** repository.
2. Upload everything in this folder to it (including the hidden `.github` folder).
3. Open the repo's **Actions** tab → **Build APK** → **Run workflow** → type your https server URL → Run.
4. After about 8–10 minutes open the finished run and download **papertradelab-apk** under *Artifacts*.
   Unzip it, copy `app-release.apk` to your phone, tap it, and allow "install from this source".

If a step fails, open it, copy the red error text and send it to me.
This APK is signed with a debug key: fine for your own phone and testers. Before giving it to the
public, set up a real signing key (section 3).

## 0b. iPhone — the honest picture first

There is no "APK for iPhone". Apple does not let an iPhone install an app file from a website.
An iOS app file is an **.ipa**, and it only runs if Apple has signed it for that phone. You have
three realistic routes; GitHub builds the file for you in all of them (macOS runners are free for
public repos and included in the free minutes for private ones):

| Route | Who can install | Cost | Push notifications | Expires |
|---|---|---|---|---|
| **A. Sideload** the unsigned IPA with Sideloadly / AltStore and a free Apple ID | you + friends who do it on their own PC | ₹0 | no | every 7 days, re-sideload |
| **B. TestFlight** (public link) | up to 10,000 users, one tap from a link | $99/yr Apple Developer | yes | each build lasts 90 days; upload a new one |
| **C. App Store** | everyone | $99/yr + Apple review | yes | never |

For a paid-subscription app, **B is what you want**: it works like your website APK (people tap a
link and install), you can update any time, and Apple review is light. C is the same build submitted
for review.

Important Apple rule for B and C: digital subscriptions sold **inside** an iOS app must use Apple's
In-App Purchase (30 % / 15 % cut). The app therefore has an `appstore` mode that hides every purchase
screen and link, exactly like the Play Store build; users subscribe on your website and simply log in.
Build with `STORE=appstore` (the TestFlight workflow defaults to it). Only route A may use
`STORE=direct` with Cashfree in the app.

### Route A — unsigned IPA (no Apple account)

1. Actions → **Build iOS IPA (unsigned, for sideloading)** → Run workflow → your https URL → Run.
2. Download **papertradelab-ios-unsigned-ipa** (≈15 min), unzip → `PaperTradeLab.ipa`.
3. On a Windows PC or Mac install **Sideloadly** (https://sideloadly.io). Plug in the iPhone, drag the
   .ipa in, type your Apple ID, Start. On the iPhone: Settings → General → VPN & Device Management →
   trust your Apple ID. (AltStore works the same way.)
4. Free Apple ID limits: the app stops opening after 7 days (just sideload again), max 3 apps per ID,
   and no push notifications. A paid developer Apple ID in Sideloadly gives 1 year and working push.

### Route B — TestFlight (recommended for users)

One-time setup is in **section 8** (about an hour, mostly clicking in Apple's website). After that:

1. Actions → **Build iOS (TestFlight / App Store)** → Run workflow → your https URL → `appstore` → Run.
2. ~20 min later the build is uploaded. App Store Connect → your app → **TestFlight** → wait until
   "Processing" finishes → add the build to a **Public Link** group (TestFlight → "+" next to
   External Testing → create group → Enable Public Link).
3. Share that link. iPhone users install the free **TestFlight** app, tap your link, tap Install. Done.
   Every new workflow run uploads a new build; testers get it automatically.

### Route C — App Store

Same build as B. In App Store Connect fill in screenshots, description, privacy answers, and submit
the TestFlight build for review (usually 1–2 days). Because the `appstore` build has no purchase
UI and no external purchase links, it falls under the normal "reader"-style rules; keep the login
screen free of "subscribe on our website" wording to avoid guideline 3.1.1 questions.

## 1. One-time setup on your own PC (about 10 minutes) — Android

(For iOS on your own machine you need a Mac with Xcode: `flutter create --platforms ios .`,
`bash .github/scripts/ios-configure.sh`, `flutter run`. Everything below is Android.)

1. Install Flutter (stable) and Android Studio: https://docs.flutter.dev/get-started/install
2. In this folder run:

       flutter create --org com.papertradelab --project-name papertradelab --platforms android .
       flutter pub get

   (`flutter create` only adds the missing `android/` folder; it does not touch `lib/`.)
   If `pub get` reports a version conflict, run `flutter pub upgrade --major-versions`.

3. Open `android/app/build.gradle` (or `build.gradle.kts`) and set **minSdk to 23**
   (`minSdkVersion 23` / `minSdk = 23`). Firebase needs it.

4. Open `android/app/src/main/AndroidManifest.xml` and add this line just above `<application`:

       <uses-permission android:name="android.permission.INTERNET"/>

   In the same file set `android:label="PaperTradeLab"`.

## 2. Run it

    flutter run --dart-define=BASE_URL=https://YOUR-DOMAIN

`BASE_URL` must be **https** — the backend marks its login cookie as Secure, so the
"log in once" session will not work over plain http.

Deploy the updated `merged_app.py` first: the app talks to the new `/api/m/*` endpoints in it.
The two new database tables (`strategy_trade`, `device_token`) are created automatically on startup.

## 3. Build the two versions

Website APK — Cashfree checkout inside the app:

    flutter build apk --release --dart-define=BASE_URL=https://YOUR-DOMAIN --dart-define=STORE=direct

Play Store bundle — no purchase screens or links (Google Play policy for digital subscriptions);
people subscribe on your site / the direct APK and simply log in:

    flutter build appbundle --release --dart-define=BASE_URL=https://YOUR-DOMAIN --dart-define=STORE=play

Before a release build, set up app signing: https://docs.flutter.dev/deployment/android#sign-the-app

iPhone build on a Mac (GitHub does this for you in section 0b):

    flutter build ipa --release --dart-define=BASE_URL=https://YOUR-DOMAIN --dart-define=STORE=appstore \
        --export-options-plist=ios/ExportOptions.plist

## 4. Payments

The app calls `/create-order` (with `source: app`), then opens `https://YOUR-DOMAIN/m/pay?sid=...` in a
browser tab on top of the app. That page runs the same Cashfree JS checkout your website uses, so no
native payment SDK is needed. While the tab is open, and when the user returns, the app polls
`/verify-payment` until the server confirms. The server decides success — never the phone.
Sandbox vs production follows `CASHFREE_ENV` on the server. Your domain must be whitelisted in the
Cashfree dashboard (it already is if website payments work).

## 5. Push notifications (optional, recommended)

1. Create a Firebase project → add an **Android** app with package `com.papertradelab.papertradelab`
   and an **iOS** app with bundle ID `com.papertradelab.papertradelab` (same ID on both).
2. Copy the values into `lib/firebase_options.dart` (`android` block from google-services.json,
   `ios` block from GoogleService-Info.plist) and set `enabled = true`. No plist/json files are
   needed in the project — the app passes the values to Firebase itself.
3. iOS only: Apple Developer → Certificates, Identifiers & Profiles → **Keys** → "+" → tick
   *Apple Push Notifications service (APNs)* → download the `.p8`. Firebase → Project settings →
   **Cloud Messaging** → Apple app configuration → upload that key (with Key ID + Team ID).
   Also tick **Push Notifications** on the App ID (section 8, step 3) — the workflow checks the
   provisioning profile and warns if it is missing. Pushes never work in sideloaded free-Apple-ID builds.
4. Server: `pip install firebase-admin`, download a service-account JSON from
   Firebase → Project settings → Service accounts, and set `FIREBASE_CREDENTIALS=/path/to/file.json`.
   The server sends to the FCM token; FCM delivers to Android directly and to iPhones through APNs,
   so the server code is the same for both.

Only users with an active subscription receive pushes (entry, stoploss moved to entry, exit).

## 8. One-time Apple setup for TestFlight / App Store (route B/C)

You need a Mac **or** a Windows PC with OpenSSL for step 4 only; everything else is in a browser.

1. **Join the Apple Developer Program** — https://developer.apple.com/programs/ ($99/year, approval
   takes 1–2 days). Note your **Team ID** (Membership details, 10 characters) → secret `APPLE_TEAM_ID`.

2. **App Store Connect API key** — https://appstoreconnect.apple.com → Users and Access →
   **Integrations** → App Store Connect API → "+" → name `github`, role **App Manager** → Generate.
   Download the `AuthKey_XXXXXXXXXX.p8` (only possible once!). Note **Key ID** → `ASC_KEY_ID`,
   **Issuer ID** (top of page) → `ASC_ISSUER_ID`. Base64 the file (step 5) → `ASC_API_KEY_P8_BASE64`.

3. **App ID** — https://developer.apple.com/account → Certificates, Identifiers & Profiles →
   Identifiers → "+" → App IDs → App → Description `PaperTradeLab`, Bundle ID **Explicit**
   `com.papertradelab.papertradelab` → tick **Push Notifications** → Register.

4. **Distribution certificate** (.p12) — Certificates → "+" → **Apple Distribution** → Continue. It
   asks for a CSR file:
   * Mac: Keychain Access → Certificate Assistant → Request a Certificate from a Certificate Authority
     → your email, "Saved to disk" → upload the CSR → download `distribution.cer` → double-click it →
     Keychain Access → My Certificates → right-click *Apple Distribution: …* → Export → `.p12`, choose a
     password → secret `IOS_CERTIFICATE_PASSWORD`.
   * Windows (OpenSSL in Git Bash):

         openssl genrsa -out dist.key 2048
         openssl req -new -key dist.key -out dist.csr -subj "/emailAddress=you@example.com/CN=PaperTradeLab/C=IN"
         # upload dist.csr, download distribution.cer, then:
         openssl x509 -in distribution.cer -inform DER -out dist.pem
         openssl pkcs12 -export -inkey dist.key -in dist.pem -out dist.p12 -legacy   # choose a password

   Base64 the .p12 (step 5) → secret `IOS_CERTIFICATE_P12_BASE64`.

5. **Provisioning profile** — Profiles → "+" → Distribution → **App Store Connect** → pick the App ID
   from step 3 → pick the certificate from step 4 → name `PaperTradeLab AppStore` → Download the
   `.mobileprovision`. Base64 it → secret `IOS_PROVISIONING_PROFILE_BASE64`.
   (If you later tick Push on the App ID, regenerate this profile and update the secret.)

   To base64 a file:  Mac/Linux `base64 -i file | pbcopy`  ·  Windows PowerShell
   `[Convert]::ToBase64String([IO.File]::ReadAllBytes("file")) | Set-Clipboard`

6. **Create the app record** — App Store Connect → My Apps → "+" → New App → iOS, name
   `PaperTradeLab`, bundle ID from step 3, SKU `papertradelab`. (The first upload fails without this.)

7. **Add the 7 secrets** to the GitHub repo: Settings → Secrets and variables → Actions →
   New repository secret: `APPLE_TEAM_ID`, `IOS_CERTIFICATE_P12_BASE64`, `IOS_CERTIFICATE_PASSWORD`,
   `IOS_PROVISIONING_PROFILE_BASE64`, `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_API_KEY_P8_BASE64`.

8. Run **Build iOS (TestFlight / App Store)**. The log prints which profile / certificate it found;
   if it fails, copy the red text and send it to me. First successful upload: App Store Connect →
   TestFlight → answer the one-time "Test Information" form, then create the Public Link (section 0b).

The certificate lasts 1 year, the profile 1 year, the API key does not expire — set a reminder.

## 9. What is different on iPhone

* `lib/firebase_options.dart` picks the Android or iOS Firebase values automatically.
* `lib/push.dart` waits for the APNs token before asking FCM for a token (iOS requirement).
* `STORE=appstore` hides purchase UI (same as `play`); `lib/support.dart` reports "iOS" in support mails.
* `.github/scripts/ios-configure.sh` sets the app name, icon (`ios_icons/`), iOS 13 minimum,
  portrait-only, mail/https link permissions and the push background mode on the generated project.
* Payments in a `direct` iOS build open the Cashfree page in an in-app Safari sheet
  (`LaunchMode.inAppBrowserView`); the server still decides success, exactly as on Android.
* Session cookies, alerts storage, fonts, charts and all screens are shared code — nothing else changes.
